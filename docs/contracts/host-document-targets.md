# Explicit unsupported document targets

A host command carries one explicit place and one requested operation. fold with a document path or an @input document whose document semantics are unsupported must refuse by a public catalog code, with nonzero status and a next action resolving to the supported form-reading operation.

Never substitute a successful fold of the place, print a different view as success or infer another operation from the document. A refusal does not invoke a signing port or admit an act. Scratch owned by the request is removed after success, refusal or cancellation; unrelated caller files remain intact.

The dispatcher, argument classification and refusal producer are shared with the native CLI wherever semantics are the same. This contract does not add a verb or duplicate parsing in a consumer. Refusal identity comes from the producer and catalog, never a regular expression over prose.

## Acceptance

The language-independent vectors are in `vectors/contracts/host-document-targets.json`. They specify required observations and effects; they do not certify the baseline implementation. Native runtime conformance requires separately captured execution evidence in two unrelated places. Existing valid evidence is retained, and no zero demand is created by publishing this contract.
