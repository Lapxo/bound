# Reading consumption and memo classification

Classification is relative to declared views and their current complete inputs. The native capture used by those views supplies input membership and digests; a directory name or writer does not establish derivation. Count physical bytes and files separately from semantic references, directory inventories, execution context and dependencies outside the measured store. Unobserved or unclassified content stays protected. This report is not an eviction authorization.

The first measured views are native lines and evidence. Repeat queries preserve every persisted byte after warm-up and preserve their identities and text. A declared reconstructible fixture is tested by removal and reconstitution; this establishes only its status for those measured views and snapshot. Unreferenced digest-addressed content remains unclassified, even when these views do not consume it. Missing consumed input must reopen or refuse, never return a retained successful result. Other views and retention commitments may consume what these views do not.

A 64 MiB unreferenced blob is included in the bounded vector. The separately reported 53 GB store incident is a received consumer observation, not reproduced or verified here. No consumer repository is read by this vector. There is no claim that a 64 MiB fixture verifies the entire incident or that all fold views are classified.

This region adds no garbage-collection verb, automatic eviction, LRU, hidden query write or new wire form. Actual eviction requires its own explicit receiver-owned maintenance contract and proof of preserved authority, in-progress acts, pins and retained content. It remains open, not established by zero growth on unchanged queries.
