# Native semantic parity vectors

The `bound-conformance@1` JSON suite pins exact UTF-8 request and response bytes for standing fold, exact withdrawal, regional aggregation and verified module inventory. JSON is acceptance data, not a new wire form or a command dispatcher. A runtime adapter delegates to its implementation; the native test adapter delegates to the same functions used by Bound. The existing receiver-pinned `runConformance` verifier compares bytes and coverage. No alternative evaluator is introduced.

Each request contains its initial lines or snapshots, selected operation and all required policy. Order is the supplied effective order; do not sort away disagreements. Responses use JSON serialization with the declared property order, then one LF. Integers in these fixtures are within the exact interoperable range. Digests are SHA-256 of exact UTF-8 bytes. No filesystem path, production key, locale, clock, timestamp or compressed container participates. A logical module coordinate is not a host path.

Fold preserves distinct inscriptions and the native output order. A withdrawal selects exact stated fields other than its envelope and value: an equal value in another scope is not retired. Regional aggregation preserves each declared region and its ancestors; this is the existing regional fold, not a new filtering evaluator. Inventory declares its real unit, module; unreachable members do not enter executable inventory. Source/version declarations are not publisher authentication.

The frozen expected outputs are native baseline observations, reviewable byte by byte. Two unrelated input domains exercise all four operations. A failing stub, altered expected byte and altered selected input must not pass. The suite also refuses a changed suite under its original pin. Native agreement does not certify a second implementation, mathematical correctness beyond the named contracts, independent construction or platform portability. Operational elapsed time is separate evidence.
