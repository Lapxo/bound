# Deterministic signer coverage diagnostics

Use the existing authority and coverage judge. A signer-coverage refusal identifies the public keyId and the first uncovered scope under canonical byte ordering, in bounded returned diagnostics or its structured refusal record. The producer, catalog code and next action must resolve through the existing catalog.

The failure must precede signature acquisition and act visibility. Do not fall back to another signer, substitute a grant, normalize a scope into coverage or expose private key material or unrelated input contents. Equal payloads do not authorize another scope.

The record and selected uncovered scope are independent of offered-record order. All records remain checked; naming the first failure is diagnostic, not permission to ignore later scopes. Reuse signer-mismatch, unbound-signer, installed-instrument pin and native serialization contracts already paid by the baseline; this region does not reimplement them.

## Acceptance

The language-independent vectors are in `vectors/contracts/signer-coverage-diagnostics.json`. They specify required observations and effects; they do not certify the baseline implementation. Native runtime conformance requires separately captured execution evidence in two unrelated places. Existing valid evidence is retained, and no zero demand is created by publishing this contract.
