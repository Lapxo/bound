# Profile preparation and native meaning

A `prepared` profile is not a native act receipt. Its inherited and local statements remain evidence for composition. For a field declared with mode `meet`, the effective value is the selected Topos lattice meet of every inherited and local constraint.

The installed native consumer vector checks this distinction for interval and alphabet fields in two unrelated places. Narrowing prepares and lands through the actual CLI. Witnessed widening also prepares and lands its authenticated statements, while the actual effective native standing remains the ancestor/local meet. In particular, a witnessed local interval `0..9` over an inherited `0..5` still composes to `0..5`; the witness does not erase the ancestor. Additions have no ancestor and receive their own actual act receipt.

The vector compares both prepared composition and effective admitted standing with `composePolicy` and the selected lattice's `meet` and `leq` operations. It defines no alternative interval or alphabet arithmetic. Claims that a raw prepared lot necessarily forks were removed after the actual native implementation demonstrated compatible distributive composition. That test correction changes no runtime semantics.

An application intending to revise an ancestor must explicitly withdraw or revise the prior native inscription under the existing admission rules. Returning `prepared`, accepting a witness-shaped context, and actually persisting an authorized revision are separate events and must be reported separately.
