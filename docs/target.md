# Project cards

A project card binds a project's accepted requirements to explicitly measured inputs. Its TARGET is a contract, its scan is an observation, and its judgement is evidence. None substitutes for the others.

The concrete Bound card lives in the sibling `bound-target/` directory. It contains a normal `TARGET.bound`, a canonical input scan in `inputs.bound`, and review instructions. It contains no old ledger, private key, inherited epoch, retired provider alias, object scene or birth animation.

The current card is unsigned and not admitted. Its file folds establish readable standing lines, not project integrity, paid requirements or an accepted release. The original instrument and its authority history are unchanged.

Source coordinates belong to host input declarations. They do not become object rest. File-byte digests are artifact identities; the scan is not relabelled as a selected topos standing. The wire, forms and authority contract remain Topos's responsibility.

A scan cannot update the accepted requirements. On a PR, the judge must read the team's accepted TARGET independently of the proposed source revision. Changed requirements need explicit review; absent readers and unread demands cannot establish success. The job must preserve genuine refusals and native receipts rather than creating its own passing JSON.

A scanner cannot certify an origin by naming itself. A second receipt does not add an origin. Signatures require admitted authority; prior signatures cannot be reauthored or assigned a new epoch. No signing, new admission, workflow installation or release has been performed by preparing this card.
